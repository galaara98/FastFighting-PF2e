# FastFighting PF2e: developer notes

What the module does at the table is in [README.md](README.md). FastFighting Core's API, hooks and adapter contract are in [its developer docs](https://github.com/galaara98/FastFighting/blob/main/CODING_README.md).

This module is also the reference for writing a FastFighting helper for another system: start from `scripts/main.js` and `scripts/adapter.js`.

## How it plugs into the core

- **module.json** requires `fast-fighting` 0.5.0 or later (and, at runtime, its API 21 to 24: `main.js` `KNOWN_API`) and the `pf2e` system 8.0.0 or later, on Foundry 14. It loads one esmodule, `scripts/main.js`, and one language file, `languages/en.json`.
- **scripts/main.js**
  - `init`: registers the Lore-Collector advantage setting (`lore.js`: key `loreBoost`, world scope, 1.25 to 3 in steps of 0.05, default 2, through the core's `numberSetting`).
  - `fastFighting.init` (receives the core's `api`): outside a `pf2e` world it logs a warning and stays inactive. The core's API version is `major.bug` (`api.version` "24.0", `api.major`, `api.bug`), and whether this helper works with a core is its own call (the core never refuses a helper): `KNOWN_API` lists the majors it's known to work with ([21, 22, 23, 24]. 21: an outcome for another alone, `notSelf`; a heal shown as PF2e's healing card and applied its way; what an effect laid, whose, and the core's `tokenOf` and `audience` for a card naming who got it; what the table settles itself, `leaveToTable`. 22: the planner's fights on background workers, `workerRules`, below; a core of 21 never asks for it. 23: `spec.aptitudes`, below; an older core leaves it unread. 24: the engine's advantage on a roll it asks for (rollStrike, rollSave, rollCheck), which PF2e, having none, ignores. The core's CODING_README has them all). A core older than the oldest gets a console error and a permanent `FFPF2E.CoreTooOld` notification, and the helper stays out; any other major it doesn't know, it runs with, and the GM is told once at ready (`FFPF2E.CoreUntested`). Add a major to `KNOWN_API` once the helper has been tried with it. Then it calls `api.registerAdapter("pf2e", Pf2eAdapter, { priority: 10, source: MODULE_ID })`, `api.adviseTranslation(MODULE_ID, game.system.title, KNOWN_TRANSLATIONS)` (the PF2e translation modules it knows, by language; in a language other than English, the settings recommend the one that isn't on) and `api.keepEnglish(MODULE_ID)` (`hardcoded-toEN.json`).
  - `ready`: warns a GM with `FFPF2E.NeedsCore` when the core isn't active.
  - `renderChatMessageHTML` and `getChatMessageContextOptions`: no Apply on the damage cards FastFighting applies itself (`cards.js`, below).
- **scripts/core.js** re-exports `../../fast-fighting/scripts/core-api.js`, the one path into the core. Both modules sit side by side in `Data/modules`; the tests alias the path to the core repository (`vitest.config.js`).
- **When the core falls short:** if new functionality needs something the core can't play close enough with what it already offers, request a new core hook. Don't force a poor fit or work around the core.

## The adapter (scripts/adapter.js)

`Pf2eAdapter extends SystemAdapter` (`systemId` `"pf2e"`). Data paths are verified against pf2e 8.6.0 on Foundry v14.

- **Reading:** `canHandle`, `toCombatantSpec(tokenDoc)` and its private readers (`#strikes`, `#elementalBlasts`, `#spells`, `#summon`, `#spellSupport`, `#selfEffects`, `#abilities`, `#glossary` (`glossary.js`), `#auras`, `#marks`, `#mending`, `#reactions` (a champion's for an ally: `champion.js`; any other: `reactions-item.js`), `#skillActions`, `#consumables`, `#poisons`, `#feats`, `#facts`, `#senses`, `#conditions`, `#persistent`, `#valuables`, `#social`, `#recallKnowledge`), `describeRegionBehavior`, `itemCatalog`, `term`, `biography`.
- **Reload and ammunition** (`ammo.js`, PF2e 8.6's data): a Strike's reload is its weapon's `system.reload.value` (`-` none: thrown weapons, bombs; `0` to `3`; `10` a minute, Infinity), a creature's attack's `reload-N` trait (`reload-1-min` a minute): the core's `action.reload` (API 20), apart from the Strike's cost of 1. It's loaded as its sheet has it (`loadedOf`: a character's weapon, the shots loaded in its subitems out of its `capacity`, its ammunition's or its capacity-N trait's), `loaded` and `capacity`; a creature's attack says nothing, and starts loaded. The core counts a Reload where it's empty, and a shot empties it; a Reload isn't split over turns (the GM's call in PF2e), and a minute's never fits a fight (its loaded shot only). A bow (reload 0) is always ready while it has ammunition; a repeating weapon shoots from its magazines' uses, its magazine change not played; a capacity weapon's Interact to the next chamber not played. A character's weapon whose Strike spends ammunition (`system.ammo` not built in, `system.expend` a shot) shoots from the core's `action.ammo` (`ammo:<weapon id>`, `ammoCost` the expend over 1): its rounds loaded (`system.subitems`) and carried, compatible by PF2e's own `isAmmoFor`, not stowed, a magazine by its uses (`roundsOf`; `readLiveState` reads them each turn). With none, the Strike stays on the spec with no shot, so ammunition picked up mid-fight counts. A creature's attack spends none (PF2e's NPC Strikes don't).
- **In hand** (the core's gear, API 20; `ready.js`): each Strike's weapon is a gear (`gear`: `<actor>.gear.<item>`, `gearKey`), and a character's not in hand (PF2e's `ready` false) costs its own Draw or Retrieve first (`drawCost`: its auxiliary action's actions, `drawActions`; Quick Draw none); a bomb is drawn again for each throw (`drawEach`). A healing potion likewise (and the core's `administer`, reach 5: a Medic may give it to a friend beside it, as PF2e lets one administer a potion): `drawCost` by where it's kept (`retrieveActions`: held 0, worn 1, stowed 1, or 2 from a backpack or a held container, as PF2e reckons a Retrieve), drawn again for each (`drawEach`). `readLiveState` reads them each turn (`gearOnSheet`: in hand or not, loaded).
- **Getting ready in a live battle** (the core's `readyGear`, API 20; `ready.js` `readyPf2eGear`): each step a creature FastFighting plays takes, on its sheet as PF2e does it, with PF2e's own card, as the turn reaches it: a Draw by its Strike's own auxiliary action with the hands it needs (PF2e's Interact card; a secret creature's whispered), a potion got out (`actor.changeCarryType`, held in a hand, with the Interact card PF2e writes for a Retrieve: its own templates and words), a Reload (a shot's round of its own ammunition loaded, `attach`, as the sheet's Reload does, with the card PF2e's reloader posts: 8.6.1 posts it only from that window, so it's written the same way), a Stand (PF2e's own Stand action, `game.pf2e.actions`: its card, prone off). Each returns its undo record (the item's equipped state and container; the ammunition's `ammoUndo`; the prone condition), for Rewind.
- **Traits on actions:** every action carries its item's traits (the core's situational saves match them: `spec.saveVs`); a spell also carries its spellcasting entry's tradition, as PF2e's own roll options do (`item:trait:arcane`), and a magic weapon's Strike `magical` (PF2e's `item:magical`: its runes too).
- **Immunities, weaknesses and resistances** (`iwrOf`, for `iwr.js`): as PF2e prepared them (`actor.attributes`), with each one's exceptions (`iwr.except`) and a resistance's `doubleVs`. Void healing (`spec.voidHealing`): PF2e's `negativeHealing` (the undead, or an ability's rule element). A Strike's `materials` (`strikeMaterials`: its weapon's precious material, a creature's attack's material traits, and the strike adjustments PF2e's damage roll calls, against `CONFIG.PF2E.materialDamageEffects`) and `propertyRunes` (`propertyRunesOf`: ghost touch).
- **Lay on Hands and Touch of the Void** (`touch-heals.js`, by slug: `TOUCH_HEALS`): a champion's touch that heals one kind of creature and harms the other, both only in its variants (its overlays, PF2e's "(Healing)" and "(Vs. Undead)"), never in its own damage; its linked effect alone would read as a buff on the champion. Built as what it does (`#touchHeal`): a heal by touch (`reach` 5) of its healing variant at the rank it's cast at (`variantOf`: the overlay's formula, heightened by its interval: 6, 12 at rank 2), for whom its trait mends (vitality the living, void the undead: `iwr.js` `healsIt`); Lay on Hands also lays its linked effect's unpredicated bonus (+2 AC, 1 round) on anyone it heals but the champion (`ward`: the core's outcome `notSelf`, API 21), that effect on the sheet (`effectRef`). And `<id>.harm`, a touch with a basic save of its harming variant (1d6 a rank), `failed` (-2 AC, 1 round) on a failure: a save rider, which the engine keeps itself (the core lays a rider's outcome by its label, not as the spell's effect). Left out: Touch of the Void's +2 damage for the champion healing itself. No buff is built from either. In a live battle each use is its variant (`action-roll.js` `asUsed`: PF2e's `loadVariant`, the overlay `touchOverlay` names, at the cast rank): its card (`useAction`) and the harm's damage (`rollDamage`). Other focus spells whose healing is in their effects already read as buffs (Life Boost's and Hymn of Healing's fast healing, its temporary HP); Soothing Words is no heal: a buff, its +1 to Will saves the core's `bySave` (`effects.js` reads a bonus to one save alone so).
- **Heal and Harm:** a spell that harms some and heals others (its damage both kinds, with a save) is a heal (for whom it mends: `rules.usable`, `iwr.js` `healsIt`) and a save action (its damage, on whom it harms: `iwr.js` `unaffected`). The use that isn't its own trait's has its own id: Heal's damage `<actor>.spell.<id>.harm`, Harm's healing `<actor>.spell.<id>.heal` (`action-roll.js` `actionItem` finds the spell by either). Heal actions and consumable heals carry their traits (a healing potion's vitality).
- **Situational saves** (`save-vs.js`, the core's `spec.saveVs`): a FlatModifier on saves (`saving-throw`, `fortitude`, `reflex`, `will`) whose predicate is only about the effect saved against: `item:trait:<t>`, `origin:action:trait:<t>` and a bare trait CONFIG.PF2E knows (`actionTraits`, `spellTraits`, `effectTraits`, `magicTraditions`) as that trait, `item:magical` as magical, `item:type:spell` as spell, `inflicts:<condition>`, `area-effect` and `area-damage` as area, `damaging-effect` as damaging, `origin:trait:<t>` as `from`; plain statements all hold, one `{or}` group any, `{not}` and `{nor}` none. PF2e leaves these out of the sheet's save totals, so nothing is counted twice; a rule with no predicate, or anything else in it (a toggle, a stance, a comparison, two or-groups), is left out. From abilities, feats, effects, heritages, ancestries, backgrounds and classes, not gear (worn or invested) or spells. Not read: AdjustDegreeOfSuccess and RollTwice on saves against some effects (Bravery's, Mythic Resilience).
- **Auras** (`auras.js`, the core's `spec.auras`): a passive ability with the aura trait or an Aura rule element whose text has a save `@Check`. Its range from the rule element's radius, an emanation `@Template`, or its text's opening feet; its traits from the item and the rule element (`needs`: visual sight, auditory hearing, olfactory smell; magical or a tradition: `magical`); its key the rule element's slug. What each degree lays: its own degree lines, the glossary entry its text calls up (`@Localize[PF2E.NPC.Abilities.Glossary.<key>]`), its save sentence and those about failing (a critical failure's clause on that alone), else its slug's glossary entry; conditions by their `@UUID[Compendium.pf2e.conditionitems.Item.<id>]` links (`CONDITION_ITEMS`, else the link's label) and by name. Its damage by `@Damage`. When and the immunity: the glossary entry its text calls up, else its words, else its slug's. The id is `<actor>.<item>`, so a live battle's save (`rollSave`) is PF2e's own with the aura's item as its origin, PF2e's bonuses against its traits included.
- **Personality and setup:** `deriveTraits` (`traits.js`), `playstyleHints` and `tacticHints` (`auto.js`), `detectLeaders` (`leadership.js`).
- **Live battles:** `supportsLive`, `commitChanges` (`commit.js`, returning an undo record), `commitBound`, `commitConcession`, `describeOutcome`, `liveOwnership`, `readLiveState`, `readTurn` and `liveOpening` (`read-turn.js`, from PF2e's chat cards), `reactionsOf`, `sheetCarries`, `conditionLabel`, `conditionChoices`, `rerollResource` (Hero Points), `resourceLabel`.
  - **A player's turn** (`readTurn`, `read-turn.js`): each card the turn made, as the engine's events, each `sure` or not (one that isn't, the GM looks at first: the core's review). A Strike and its damage; a skill action at a creature by its action's roll option (`action:<slug>`): a maneuver (`MANEUVERS`), and PF2e's social actions as talk (`SOCIAL`: Request and Make an Impression persuade, Coerce intimidates, Lie deceives). Demoralize is both: its maneuver (the frightened is the sheet's, and weighs on morale as any fear) and an intimidate talk at its degree (the core's `resolveTalk`: the persuasion track, not morale, so nothing is counted twice). A social action's card with its target and a degree is sure: it says what it was, at whom and how it went. With no target or no DC, and a plain Diplomacy, Intimidation or Deception check, it's talk the GM looks at (`TALK`, by the card's domains). An action's card is titled with PF2e's markup, so its events carry the action's own name (`words.js` `actionNameOf`: `game.pf2e.actions`).
- **Players' damage (API 19):** `damageCard` (`read-turn.js` `pf2eDamageCard`), `applyDamageCard` (`commit.js` `applyPf2eDamageCard`: PF2e's `applyDamageFromMessage` for one token, through its `actor.applyDamage`, `roll.alter(multiplier)` as its Half and Double buttons do) and `appliesPlayerDamage` (null: no PF2e setting does it). `applyDamageCard` applies FastFighting's own damage cards the same way (below), times the card's mark.
- **Strikes (API 19):** `rollStrike` (`strike-roll.js` `rollPf2eStrike`: the engine's strike id back to the sheet's Strike, the variant for `attackNumber` (MAP, no further than the third) and its `damage` or `critical` with that `mapIncreases`, with PF2e's `target` param, so no dialog and the user's targets untouched; `secret` holds Ctrl, PF2e's GM roll), for every Strike in a turn FastFighting plays and for reactions. It returns the damage card it made (`card`). Its damage card is applied through `applyDamageCard`; Shield Block's reaction spec says `applies: "shieldBlock"`, so a live battle applies a blow it blocked with PF2e's own Shield Block (`shieldBlockRequest`, which needs the shield raised, as the engine does).
  - Ammunition (`ammo.js` `readyAmmo`): PF2e's Strike refuses a weapon with too little ready, so it's readied first as a player would, from the stack PF2e's own pick names (`system.selectedAmmoId`) where it has rounds, else the compatible stack with the most: a bow (reload 0, not repeating) picks it (`system.selectedAmmoId`, as the sheet's list sets it); anything else is loaded as the sheet's Reload loads it (`weapon.attach(stack, {quantity, stack: true})`: the rounds the shot needs, a magazine at most). PF2e's Strike then spends it. The weapon and its stacks are noted before (`ammoState`) and an undo record made after the attack roll (`ammoUndo`: counts, uses, the pick, what's loaded; a stack used up made again), returned as `records` (the core's API 20) for Rewind, even where PF2e still refuses (`{records}`; the engine rolls it). Rounds the engine's own dice shot beyond what the sheet spent come off the stack with the most in `commitChanges` (`spendRounds`).
  - A champion's reaction for an ally (`champion.js`) says `applies: "effect:<its item id>"` when its card links an effect that resists all damage (`granted.js`: Champion's Resistance). The core hands it to `applyDamageCard` with `{by: the champion's token}`; `commit.js` `friendsGrant` lays the effect on the target's contextual copy for this blow only, as PF2e lays its ephemeral effects, with the champion and the reaction as its origin (as when the link is dragged from the card), so `@item.origin.level` is the champion's. PF2e's `applyDamage` applies the resistance and its damage-taken card shows it. The sheet never holds the effect, so nothing is removed or undone. The spec's `reduce` (`resistanceOf`: 2 + level) is the engine's estimate; the core takes what the sheet lost instead, so the blow is lessened once. Without such a link there's no `applies`, and the engine's sum stands.
  - A spell attack (`spellAttackFor`: the id `<actor>.spell.<spell id>`, a spell with the attack trait, damage and a spellcasting entry) is rolled as its card's buttons roll it: `spell.rollAttack(event, attackNumber + 1, {target: the target's actor})` (PF2e finds the token by its actor's tokens on this canvas, so only at a target drawn here; else null, the engine's roll), and on a hit `spell.rollDamage(event)` at the spell's rank. PF2e's spell damage takes no target but the user's own targets (left untouched; a GM's, none as a rule), so the damage card has no target or, with the GM targeting something, that one. PF2e doesn't double a spell's damage roll on a critical hit, only its Double button as it's applied: then `byType` is doubled and the card is marked to be applied doubled (`cards.js`). A spell attack with no damage is crowd control, the engine's roll.
- **An action's card and its damage (API 19):** `useAction` and `rollDamage` (`action-roll.js`). The action's item by its id: `<actor>.spell.<id>` a spell, `<actor>.self.<id>` an action or feat (Rage), `<actor>.item.<id>` a consumable, `<actor>.<id>` an action or feat (an ability: `abilities.js`), `<actor>.<id>.<use>` an ability put to a use of its own (`maneuvers.js`: Grab's Grapple, `.grapple`, whose check is PF2e's own Grapple by `check-roll.js` `ACTIONS`; kept up, `.keep`); never a melee item (its `toMessage` rolls the Strike).
  - `useAction`: a spell's card as its spellcasting entry's `cast` posts it, without `consume`: `spell.toMessage(null, {actualCast: true, data: {castRank: rank}, mode})`, so no slot, focus point or use is spent; PF2e places a template only from the card's button. Any other item's card as its sheet posts it (`item.toMessage(null, {mode})`, nothing used; a consumable's card keeps its Use button). `mode` is `gm` (a player's, `blind`) when `secret`. Null for an action with no item (Take Cover, Aid, Battle Medicine, a Strike) and for a spell attack `rollStrike` rolls (its attack card shows the spell); a spell attack it can't roll (a target not drawn here) shows its card. The core asks for spells, save and auto actions, and any buff or heal with no check of its own.
  - `rollDamage`: a spell's damage as its card's Damage button rolls it (`spell.rollDamage(event)`, `secret` holding Ctrl); an ability's by the first `@Damage` link on its card (`card`, useAction's) that isn't persistent damage alone, clicked as the GM would: the card is rendered (`message.renderHTML()`) and the link handed to `CONFIG.ux.TextEditor._onClickInlineRoll` (PF2e's inline damage: the card's speaker and item, an elite or weak creature's adjustment, rule elements). PF2e's inline damage takes no Ctrl, so a `secret` roll adds PF2e's `secret` roll option to the link. `damage.byType` is as rolled, before resistances, in PF2e's damage types (the rules' keys); persistent damage is left out, as `rollStrike`'s is (PF2e's application lays it as its condition, which `readLiveState` reads). An ability with no damage link that deals a Strike's damage with no roll of its own (Rend: `glossary.js` gives its action `strikeOf`, the named Strike's id, which the core passes in `action`) is rolled with that Strike's own Damage (`strike.damage({event, target})`, at the `target` the core passes), its card marked like any other. Null (the engine rolls it, and the core shows its dice) for a spell attack (`rollStrike`'s), Force Barrage (`PART_CARDS`: its card is one missile's), a spell with no damage, a consumable, an ability with no damage link and no Strike named (Trample) or no card. Nothing is applied: the core applies each target's share with `applyDamageCard` and `multiplier` (0.5 a basic save's success, 2 a critical failure).
  - **No damage applied twice** (`cards.js`): every damage card `rollStrike`, `rollDamage` and `showTableRoll` make is marked (`flags["fast-fighting-pf2e"].rolled: {times}`, `setFlag`). FastFighting applies it (or, a reaction having lessened the blow, its own sum, or nothing where a flat check turned the hit into a miss), so `main.js` takes its Apply buttons off as it renders (`renderChatMessageHTML`: `.damage-application` emptied, a `FFPF2E.DamageHandled` line in their place) and PF2e's Apply entries off its chat menu (`getChatMessageContextOptions`: the `PF2E.DamageButton.*` entries hidden on it), for GMs and players alike. The mark counts only on a card a GM made (`rolledHere`; FastFighting rolls in the GM's browser): anyone may flag their own card, so a player's card is applied once (`timesOf`). A card whose damage the live battle applied itself, whoever made it (a reaction a player rolled on FastFighting's asking, a player's damage card applied for them), loses its Apply buttons and menu entries too in the browser of the GM who plays the battle (`handled`): by the ids the core noted as it applied them (core-api `damageApplied`, API 20), never by the card's flags. Other cards are as PF2e has them.
- **The engine's own dice as PF2e's cards (API 20):** `showTableRoll` (`table-cards.js` `showPf2eTableRoll`). A roll FastFighting made with its own dice in a live battle (where PF2e didn't roll it: a Strike it refused, a save or check no roller of its took, a flat check, damage the engine rolled, healing) is posted as PF2e posts that roll, one card a roll, to whom the core says (`audience` "gm": PF2e's GM roll). Styling only: the engine's dice and result stand; nothing PF2e does with the card changes them.
  - An attack, a save, a check or a flat check: PF2e's `CheckRoll` from the core's `rollJson` (the engine's d20, two kept for fortune or misfortune, its modifier and total), `flags.pf2e.context` of type `attack-roll`, `saving-throw`, `skill-check` or `flat-check` (an attack's or a check's target; a save's origin, whoever made it save, its target the one saving), the DC by PF2e's statistic (`armor`, a save's) and the engine's outcome. Its title is the action's name (a save with none, PF2e's "Reflex Saving Throw"; a flat check, `FFPF2E.FlatCheckFor`), its DC and result PF2e's own target-dc-result block (`resultBlock`, as PF2e's private `Check` builder writes it, PF2e's own words): the opposer's name as its nameplate shows it (PF2e's NPC name visibility), the DC to the players against a character of theirs or with PF2e's Show DCs, the result with its Show Results, the rest for the GMs. No Damage buttons (`damaging` false) and no Hero Point reroll (the roll's `isReroll`).
  - Damage and healing: PF2e's `DamageRoll`, its formula from the roll's parts (`damageFormula`, from the core's `rolledParts`): an instance per type in PF2e's order of writing, a precision or splash part flavored inside it, a critical's doubling written `2 * (...)` (a die not doubled, a deadly one, after it), healing flavored `healing`, a Strike's materials (`strikeMaterials`) on each instance; persistent damage left off (the engine lays it). A heal of so many hit points, no dice (API 21: Lay on Hands' 6), is its number alone (`{6[healing]}`). Whom it's at, under its title (`targetLine`): PF2e's own "Target: ..." (the opposer part of its `WithTarget` label; else `FFPF2E.CardTarget`), the name the GMs' alone where its nameplate hides it. PF2e parses the formula and the engine's dice are put into its own Die terms before it's evaluated (`allowInteractive: false`), so nothing is rolled; a formula PF2e reads with other dice than were written is no card (the core's plain roll). `flags.pf2e.context` as PF2e's DamagePF2e writes it: `damage-roll`, `sourceType` the roll's `source` (attack or save), its target, the outcome of an attack (`success`, `criticalSuccess`), its options (the speaker's and the item's), the item as its `origin` (by the adapter's ids: a Strike's weapon, a spell, an ability); its header PF2e's (the action's name, a save's share as the core's `Rolls.Times` says, an attack's outcome in PF2e's words). Marked as FastFighting's (`cards.js`, `rolled: {times: 1}`), so its Apply buttons are gone.
  - In a turn FastFighting plays, the core makes the engine's damage this card at once (its `card` roll) and applies it with `applyDamageCard` (`applyPf2eDamageCard`: PF2e's IWR, its "takes N damage" card, the undo record Rewind uses); everywhere else (a player's turn, the aftermath) the card is shown and the engine's sum is written with the turn's changes. A heal likewise (API 21): its healing card, then applied by PF2e (its "is healed for N" card), the one healed gaining what its sheet gained.
  - What the table settles itself (API 21: a player's character's heal or damage at another, Apply players' damage off): the core doesn't apply the card, and asks `leaveToTable` (`cards.js` `unmarkRolled`): its mark off, so PF2e's Apply buttons are back for everyone; it waits in the Battle Vantage.
  - Anything else (a recharge or cooldown die, a crit or fumble table's die, a rider's die, a roll with no token, a check with no d20): null, the core's plain roll. Every card carries the core's flags it's handed, so it's never read as a player's card and Rewind deletes it with its turn. The named imports from core-api (`rolledParts`, `rollJson`) need a core that exports them (API 20).
- **Saves and checks (API 19):** `rollSave` and `rollCheck` (`check-roll.js`), against the engine's DC as `{value}`, no dialog, PF2e's GM roll when `secret`; the details are in its header.
  - A save: `actor.saves[key]` (of several keys, the best), `from`'s actor as `origin`, and the item the action's id names (`itemIn`; with no `from`, from the actor the id begins with). Not an item with the incapacitation trait: the engine's `rules.controlShift` shifts that degree.
  - A check: PF2e's own action (`game.pf2e.actions`) where it has one (`ACTIONS` by the id's last part, `PURPOSES` by purpose; Aid with the best of `AID_SKILLS`); else the statistic (`ITEM_SKILLS` for a feat or ability, Medicine to heal, the skill the spec names by slug or label, talk by its kind of pitch). With `against` and the target's token drawn, the target goes along and the DC carries `slug: against`. Null (the engine rolls it) for `cast`, an Aid whose best way is a Strike (PF2e's Aid rolls a skill), and anything it can't place; never `{gm: true}`.
  - A Seek (purpose `seek`, the core's patrol: `behavior/patrol.js`): PF2e's own Seek action (`game.pf2e.actions` `seek`), no target, against the engine's DC (the highest Stealth DC of those it may find there), its secret trait rolling it for the GMs; without the action (an older PF2e), Perception as the sheet rolls it.
  - Talk (purpose `talk`, the core's pitch: its kind as the action's name, no action id) at a creature whose token is drawn here: PF2e's own action for that kind (`TALK_ACTIONS`), the target with it, the DC `{value, slug}` its Will (a lie, its Perception; the core's `against` where it names one), no dialog. Persuade is Request in a fight, Make an Impression while a standoff holds (the core's `standoff`, API 20: no blows yet; its attitude steps go as the engine's sway does); intimidate is Coerce, never Demoralize (the engine sways, it doesn't frighten, and Demoralize's card would promise frightened); deceive is Lie, whose secret trait has PF2e roll it for the GMs. Without the action (an older PF2e), or the target's token here (PF2e would take the user's own targets), the skill alone, as before; a taunt (the core's goad, its own action id) is always the skill. An action that rolled nothing is the engine's, not the skill as well.
  - Multiple attack penalty: the core's `attackNumber` for a check with the attack trait (as the engine counted it for its own penalty; null, none): PF2e's action takes it as `multipleAttackPenalty`, an item's check as `attackNumber` + 1. One with neither is left to the engine. An Escape takes none, as the engine's doesn't, though PF2e's has the attack trait.
  - The helper's rules that roll a check or save themselves ask the same way (core-api `systemRolled`, its answer as `rollCheck`'s `rolled`, the engine's DC kept; no answer, the engine's dice): `breakFree`'s Escape (`escape`), `stopBleeding` (`firstAid`, its action id ending in `stop-bleeding`, Administer First Aid's variant), `retch` (a `fortitude` save), `tumbleThrough` (`tumble`, `against: "reflex"`, the foe its target: PF2e's `tumble-through` action) and every flat check (`rules.js` `flatRoll`, `flat`: PF2e's flat check, `game.pf2e.Check.roll` with an empty `CheckModifier`, `type: "flat-check"`, titled `FFPF2E.FlatCheckFor` with the rules' label). The flat checks: an attack's against one hidden from it (the core's `hiddenFrom`: not one it found with a Seek since it hid), concealed or by one dazzled (`adjustRoll`, the attacker's at its target), a targeted spell's save (`adjustRoll`, the caster's), stupefied (`disrupted`), persistent damage (`persistentFlatCheck(rng, {run, unit, type})`, its type in the label), dropping and rolling (`persistentRemedy`), and the bleeder's after Administer First Aid (`stopBleeding`). `adjustRoll` is called after a strike or save the system rolled too (`ctx.rolled`): PF2e rolls no flat check of its own, so the flat check stands, and `adjustRoll` does nothing else to that roll (a hit's damage card already in the chat isn't applied once the flat check makes it a miss). Still the engine's dice: `cutFree` and the dying recovery check (`recoveryCheck` has no run to ask with, and PF2e's own `rollRecovery` would change the sheet itself).
  - **The engine's own dice, shown** (the core's table rolls, CODING_README **Table rolls**): where these rules roll a d20 or damage themselves, they record it on the rng (`rng.mark?.()`, `rng.record?.(at, roll)`: nothing in a simulation or with an older core), so a live battle posts it as a real roll. `flatRoll`'s d20 (a flat check, its label and DC), `recoveryCheck` (a flat check against 10 + dying; PF2e's own recovery automation owns it in a turn, so it's the aftermath's), `surprise` (each sneak's Stealth against its foes' best Perception DC, posted with the opening), and `cutFree` (its Strike and its damage, doubled on a critical hit). Their checks through the core's `rollCheck` record themselves, labelled: Tumble Through and Escape (`actionName`), Administer First Aid on a bleed, retching. The named imports from core-api need a core that exports them (API 19).
- **Surprise (API 19):** `rules.surprise` (`rules.js`, the planner's Follow System): hidden tokens (Avoiding Notice) roll Stealth for initiative (`stealthSides`), and one whose Stealth (d20 + Stealth) beats every foe's Perception DC starts `hidden`, its first Strike finding its target off-guard; no surprise round, no one surprised.
- **Who got which effect (API 21):** `commit.js` `tellGiven`, as a turn is written: a short card from whoever gave it (`options.tokenOf`, the speaker), after the action's own card, for each effect laid (`effects.added`, and the core's `laid`: conditions an effect lays alone) where no card of PF2e's names whom it went to (`rollNames`: not a save's, a check's or an attack's), nor one an action only its user takes laid on itself (`ownOnly`): "Lay on Hands → Lem (+2 AC)" (`FFPF2E.Given`), its effect linked to drag (`effectLink`: PF2e's anchor, as PF2e links an applied effect; PF2e has no card naming another who got one). For the GMs alone where either is hidden from the players (`options.audience`), the name the GMs' alone where its nameplate hides it. One the table settles itself (`changes.left`) is named, not laid (`FFPF2E.GivenWaits`): its players drag it from the action's card. The core keeps these cards with the turn, so Rewind deletes them. Nothing with an older core.
- **The planner's fights on background workers (API 22):** `workerRules` gives `rules.js` (its url from the adapter's own, `import.meta.url`) and its export `pf2eRules`, no `data`: the rules read no setting as they play (the Lore-Collector's advantage, `loreBoost`, is read as the spec is built: `sizeUp.boost`). The core's workers import it with nothing of Foundry's about, so `rules.js` and everything it imports stay off the Foundry side (no sheets, cards or chat: `holds.js` keeps `IMPLIES` for it), and their labels go through `words.js`, whose Foundry reads are all optional (a worker's labels are keys). `tests/workers-pf2e.test.js` checks the imports, that loading it on a bare thread reads none of Foundry's globals, and that PF2e batches on real threads give what the main thread gives.
- **Other:** `rules` (`pf2eRules`), `supportsLoot`.

Effect items are fetched once a session (`granted.js` `EFFECT_CACHE`); a summon spell's creature comes from the Actor compendiums, the Monster Core first, never a unique one (`CREATURE_CACHE`, `SUMMON_LEVEL`, `SUMMON_TRAITS`). In a world translated with Babele, an item's rules are read from its English original (the core's `englishName` and `englishDescription`), so they parse in any language.

## Words and translation

Every word this module shows is in `languages/en.json`; the code holds keys, never English. Translating takes only a copy of that file (see **Translating** in [the core's README](https://github.com/galaara98/FastFighting)). `npm run test:reworded` runs the tests with every word in the language files reworded, so no test depends on the wording.

`reading/en.json` holds the patterns this module reads PF2e's own text by, where an item's data says nothing: a reaction's Trigger line and Effect, an ability's Requirements, an aura's. A translation is a copy named for its language (`reading/de.json`), tried before the English; text it doesn't match is read as English, else not at all. The patterns run on every actor's items in the GM's browser, a player's own too, so each must finish quickly on any text: no group whose words split many ways (`(?:[\w'-]+ ?){1,4}`; write `[\w'-]+(?: [\w'-]+){0,3}`), and no word run before a fixed word that a match may start inside of at every hyphen (`\b[\w-]+ spell`; write `(?= spell)(?<=\w[\w-]*) spell`, the word first). `tests/reading-speed-pf2e.test.js` holds every pattern under 50 ms on 3,000 characters made to slow it, and the readers run them on no more than real text has (`trigger-lines.js` `READ_MOST`: a Trigger or Requirements line 300 characters, else not read; an Effect's sentence 1,000, else no reaction built; a text read whole, the first 4,000). Its sections:
- `self`: the words a line is read by with the creature as "you" (`you`, `your`, `articles` before its whole name, `definite` before a word of its name or kind, `plain` words that are never a name, `stock` phrases for the creature, `possessive`, `replace` pairs).
- `triggers`: `[{name, trigger, pattern, whole?, crit?, melee?, ranged?, range?}]`, tried in order, the first that matches filing the line (`trigger-lines.js`). A `whole` entry matches a whole line (`^...$`) and says all it means: only those build reactions; its named groups add filters (`crit`, `melee`, `ranged`, `range`, `adjacent`, `reach`, `strike`, `types`; a name may end in a digit for a second place), and `alsoOn` the other moments it answers. The rest file lines for the coverage scan (`tools/coverage-triggers.mjs` reads this section, one grammar for both).
- `effects`: `[{name, effect, pattern, range?}]` over an Effect's sentences: `strike` (a `strike` group names its own Strike), `ac` (`value`), `around` (`range`), `recharge` (`action`), `foe` (who a condition is laid on), `onFail`, `unless` (a sentence left out), `notLaid` (a condition only checked for), `selfHarm` and `unclear` (no reaction built).
- `requirements` (`requirements.js`): entries `{means, pattern}`, each pattern matching a whole line, lower case, its links as their labels. `line` finds the Requirements line in an ability's text (its `line` group); `holding`, `lastHit` (a `strike` group names the Strike), `target` (a `conditions` group, each word the core's condition key or a `word` entry's, or the entry's own `is` list), `self` (`is`) and `shieldRaised` say what it needs; `word` maps a condition word the core hasn't (`dying` is `unconscious`); `rolled` marks an effect that rolls for itself (a Strike it makes), whose damage then isn't simply dealt. A line no entry matches can't be expressed, and the ability isn't used.
- `multiattack` (`glossary.js` `countedStrikes`): a list of `{pattern, numbers}`, tried in order, the first that finds any counting: a count word (`n`) and a Strike's name (`strike`) before the word Strike, global over the text; `numbers` gives each count word's value ("two claw Strikes and one jaws Strike").
- `auras` (`auras.js`): an aura's opening feet, when it goes off, the clauses about failing and critically failing, the sentence about immunity, the degree headings.

`hardcoded-toEN.json` lists words that stay in English for now, whatever the reader's language: keys of `languages/en.json`, or a group (`"FFPF2E.Action"`), whose translation would contradict a game system that isn't translated yet. It holds the date it was last updated (`lastUpdated`) and the list (`keys`), and is edited like the language files.

## Development

Check out this repository next to the core (`../FastFighting`), then run `npm install` and `npm test`. The tests use the core through `vitest.config.js`; point them elsewhere with `FASTFIGHTING_CORE`. Junction or symlink the folder into Foundry as `Data/modules/fast-fighting-pf2e`.

- `npm test` (`vitest run`) and `npm run test:reworded` (`vitest run --mode reworded`). `tests/setup.js` gives each test a fake `game.i18n` that reads this module's and the core's language files (`tests/foundry-i18n.js`).
- `.github/workflows/test.yml` runs both on every push to `main` and every pull request, with the core checked out beside this repository.
- `node tools/coverage.mjs --out docs/coverage.md` (dev only, not released): what of PF2e's creature abilities and character options the helper understands, by slug and frequency, with reaction triggers against the core's master list ([docs/coverage.md](docs/coverage.md); options and approximations in the tool's header). It runs the helper's pure readers on the pack data with `reading/en.json`'s words (abilities and their requirements, auras, situational saves, the glossary's standard abilities, reactions); `NO_FIGHT_EFFECT` counts as known, never a gap. Its trigger grammar is `reading/en.json`'s (`tools/coverage-triggers.mjs`); its "plays" column counts the reactions the helper builds. `--pf2e` takes an install, a release's unpacked `json-assets.zip` or a checkout of the system at a release tag (`tools/coverage-packs.mjs`).
- `.github/workflows/release.yml` runs on a `v*` tag: it tests in a job with read-only rights, then, in a job that alone may write (`contents: write`, nothing from npm), sets `version` and `download` in module.json, zips `module.json`, `scripts`, `languages`, `reading`, `hardcoded-toEN.json`, `README.md` and `LICENSE` into `module.zip`, and publishes both files as a GitHub release.

## Reviewing system updates

So a PF2e update or errata never means reviewing every item. Dev only: `tools/` and `review/` stay out of the release zip. The shared parts (fingerprints, the files, comparing, the report) are the core's `tools/review`; `tools/review.mjs` is PF2e's part.

- **`review/ledger.json`:** one entry per special case, a PF2e slug the scripts name (quoted, or an object key): `how` (`special`; `no-fight`, `NO_FIGHT_EFFECT`; `elsewhere`, `PLAYED_ELSEWHERE`), `note` (our own line: what's special, and where), `reviewed` (the date), `system` (the PF2e version) and two fingerprints, short sha-256s: `rules` (rule elements, traits, action type and cost, frequency; a spell's casting and damage; a condition item's id) and `text` (its description). They come from PF2e's Item packs, or, for a slug only creatures have, from every creature's copy with numbers and names masked. Also `notSlugs` (kebab-case names that aren't PF2e's), `ignore` (PF2e slugs the code means something else by: a trait, a field) and `checked` (the last version fully checked). Never PF2e's text.
- **`review/snapshot.json`:** for every other creature ability and character option the coverage scan reads, a fingerprint of what the helper builds from it (numbers, ids and labels masked, over every creature that has it) and a count; and PF2e's other slugs by kind (its ability glossaries, spells, conditions, classes, ancestries, heritages, backgrounds), so a new one shows.
- **The check:** `node tools/review.mjs [--pf2e <packs>] [--out report.md]`. `--pf2e` takes what the coverage scan takes: an install, a release's unpacked `json-assets.zip` with its `system.json`, or a checkout at a release tag. It reports special cases whose structure or text changed, slugs the code names that PF2e no longer has, named slugs with no entry, auras.js `CONDITION_ITEMS` ids that moved, generic slugs whose built shape changed, and new slugs (likely special cases first: in PF2e's glossaries, like a special case's slug, or common and not understood), with links to the code.
- **Accepting:** after reviewing, `--accept <slug ...>` re-stamps those entries (a new one needs `--note "..."`; `--how` sets its kind). `--accept-generic` re-snapshots the generic readings and the system's slugs. `--notes <file>` stamps many at once (`{entries: {slug: note}, ignore: {name: why}}`). A run that accepts and leaves nothing to review sets `checked`.
- **The test:** `tests/review-ledger-pf2e.test.js` (offline, no packs) fails when the scripts name a slug with no entry, listing them: add the entry, or the name to `notSlugs` or `ignore`. A single word counts only when the snapshot lists it; `tools/review.mjs` checks the rest.
- **The workflow:** `.github/workflows/system-watch.yml` runs weekly and on demand (`version`, `dry_run`). When PF2e's latest GitHub release is newer than `checked`, it downloads that release's `json-assets.zip` and `system.json`, runs the check, keeps the report as an artifact, and opens one issue titled "PF2e <version>: what changed for FastFighting" unless one by that title exists (open or closed). Its token is only in the steps that run `gh`, never the one that reads the packs; its checkouts keep no credentials; and the report's pack text goes through the core's `code` and `plain` (no breaking out of a code span, no mentions, no links).
